# 实训学时合规与冻结服务

该服务汇聚学员签到、导师确认和请假修正事件，按培养方案与时区重放学时状态，并保存可追溯的学期冻结快照。项目还提供导师分配、证明材料、豁免复核、规则版本、名额、通知和数据留存等领域模块，供后续业务扩展时复用统一的状态与审计约束。

## 事件顺序模型

业务方提供的 `event_id` 只承担幂等键职责，格式不限（短数字、业务前缀混排均可）。事件的发生顺序完全由服务端在导入成功时分配的、按培养方案从 1 连续递增的持久化序位 `seq` 决定：

- 重放一律按 `seq` 升序；迟到补录无论编号大小，序位必然更大；
- 冻结在同一个 `BEGIN IMMEDIATE` 写事务内读取截止序位、重放并落库，
  并发导入会被写锁挡在事务外，已签发结果随后续重复冻结或补录保持不变；
- 历史冻结的截止点同时保存 `event_cutoff_seq` 与 `event_cutoff_id`，
  重启后按序位即可复现。

## 旧数据迁移

服务启动时（`app.main` 的 lifespan）会先建表再幂等执行 `app.migrations.run_migrations`：
为旧库补齐 `events.seq`、`freezes.event_cutoff_seq` 列与 `(plan_version, seq)`
唯一索引。事件序位按到达顺序（自增主键）回填，冻结截止序位结合截止编号与
当时落库快照内的事件反推，保证历史冻结继续可复现。迁移可重复执行。

## 运行方式

默认数据保存在项目目录的 SQLite 文件中。安装依赖后执行 `uvicorn app.main:app --host 127.0.0.1 --port 8000`，健康检查地址为 `/health`，业务接口位于 `/api`。


测试覆盖事件幂等导入、混合编号按服务端序位重放、迟到补录不渗入历史冻结、
跨时区与跨日学时合并、实习确认、负向修正、并发导入与冻结、旧库迁移与
重启读取、冻结快照和差异查询；运行过程中不需要单独的数据库或网络服务。
